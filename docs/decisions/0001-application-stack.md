# 0001. Application stack

Date: 2026-11-26  
Status: accepted

## Context

Moneyverse is a mobile-first web app for one user now and a few friends later, maybe self-hosted (R-20, R-21). It must be free to run (C-1) and installable (C-3). The owner leans towards a JavaScript stack (S-8). The [tech plan](../discovery/money-tracker/tech-plan.md) suggested a stack; the owner approved Turso (D-4) and, on 2026-11-26, the setup plan with Next.js and the starter pack's Next.js recipe.

## Decision

- **Next.js 16** with the App Router, TypeScript and `src/`, generated by `create-next-app` 16.4.6, on **Node 26** and **pnpm** (pinned in `packageManager`). Server actions and route handlers stay thin; business rules go in `src/server/` once they exist, with an ESLint import boundary.
- **Turso (libSQL) with Drizzle ORM** (D-4). Development and tests use a local libSQL file, so no Docker is needed. A self-hosted install uses a plain SQLite file with the same schema.
- **Hosting: Vercel Hobby** is the plan, not yet verified. H-3 (deploy login plus database and read the current free-tier limits) happens in the first feature PR, which records the result here or in a new record.

## Alternatives considered

- SvelteKit (tech plan): smaller bundles, but the owner's other projects and the starter pack recipe use Next.js.
- Postgres on Neon or Supabase (tech plan): self-hosting would then need a Postgres container; the owner chose Turso.

## Consequences

- One schema runs hosted and self-hosted; moving off Turso (RK-5) needs no schema change.
- Next.js 16 enables `cacheComponents`; nothing that depends on a session or financial data may be cached (`AGENTS.md`).
- Revisit hosting if H-3 fails, and the database if Turso's free tier changes.
